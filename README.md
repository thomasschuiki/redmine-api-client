# go-redmine-cli

OpenAPI spec tooling and CLI client for the [Redmine](https://www.redmine.org/) REST API.

## Binaries

| Binary | Purpose |
|--------|---------|
| `redmine-spec` | Validate and generate from the OpenAPI spec |
| `redmine` | CLI client for interacting with a Redmine instance |

## Install

```bash
go install github.com/tom-redmine/go-redmine-cli/cmd/redmine-spec@latest
go install github.com/tom-redmine/go-redmine-cli/cmd/redmine@latest
```

Or build from source:

```bash
git clone https://github.com/tom-redmine/go-redmine-cli.git
cd go-redmine-cli
go build -o redmine-spec ./cmd/redmine-spec
go build -o redmine ./cmd/redmine
```

## `redmine-spec` — OpenAPI Spec Tooling

### `spec validate`

Validate an OpenAPI spec for structural errors: broken `$ref` pointers, invalid
schemas, missing required fields.

```bash
redmine-spec spec validate
redmine-spec spec validate --spec docs/openapi/openapi.yaml
```

`--strict` additionally fails on contract problems such as unreferenced
component schemas:

```bash
redmine-spec spec validate --strict
```

| Flag      | Default                      | Description |
|-----------|------------------------------|-------------|
| `--spec`  | `docs/openapi/openapi.yaml`  | Spec file   |
| `--strict` | `false`                     | Enforce dead-component gate |

### `generate-models`

Generate Go model types from the bundled OpenAPI spec.

```bash
redmine-spec generate-models
redmine-spec generate-models --spec docs/openapi/openapi.yaml --out internal/models
```

| Flag       | Default                        | Description            |
|------------|--------------------------------|------------------------|
| `--spec`   | `docs/openapi/openapi.yaml`   | Bundled spec file      |
| `--out`    | `internal/models`             | Output directory       |
| `--package` | `models`                      | Go package name        |

### Contract and Generated Model Workflow

`plugin/redmine_openapi_generator/lib/redmine_openapi_generator/contract.rb` is
the upstream source of the Redmine API payload shapes. The plugin combines that
curated contract with live Redmine route and `accept_api_auth` discovery to emit
an OpenAPI specification.

The dependency direction is intentionally one-way:

```text
contract.rb
    ↓
OpenAPI spec (docs/openapi/openapi.yaml and testdata/openapi/)
    ↓ redmine-spec + libopenapi
internal/models/models.go
    ↓
hand-written HTTP methods in internal/client/
```

`internal/models/models.go` is generated and should not be edited directly. The
client methods remain hand-written, but their request and response types alias
the generated models. When an API shape changes, update the contract first, then
regenerate the spec and models. The Go models cannot be the plugin's source of
truth because they are downstream of the OpenAPI output and are not available to
the Ruby plugin running inside Redmine.

### Regenerating the Spec from Redmine

The spec is auto-generated by the `redmine_openapi_generator` plugin, which runs
inside a Redmine Docker container and introspects routes and API controllers,
with payload shapes from a curated contract. See
`plugin/redmine_openapi_generator/README.md` for details.

```bash
./scripts/gen-openapi-spec.sh [redmine_version] [output_path]
```

```bash
# Regenerate for latest Redmine
./scripts/gen-openapi-spec.sh latest

# Regenerate for a specific version
./scripts/gen-openapi-spec.sh 7.0.2 docs/openapi/openapi.yaml
```

Versioned snapshots are committed under `testdata/openapi/` and pinned by the
snapshot tests:

```bash
./scripts/gen-spec-snapshots.sh
```

### End-to-End: Refreshing the Spec When Redmine Changes

1. **Regenerate the spec** from a Redmine Docker container:

   ```bash
   ./scripts/gen-openapi-spec.sh latest docs/openapi/openapi.yaml
   ```

2. **Validate** the spec (strict, so dead components fail):

   ```bash
   redmine-spec spec validate --strict
   ```

3. **Regenerate the versioned snapshots** and commit them:

   ```bash
   ./scripts/gen-spec-snapshots.sh
   ```

4. **Re-generate Go models**:

   ```bash
   redmine-spec generate-models
   ```

5. **Run the full test suite** (snapshot tests pin the contract surface per
   version):

   ```bash
   go test ./...
   ```

## `redmine` — Redmine CLI Client

A thin CLI wrapper around the Redmine API. Designed for programmatic use
(e.g., coding agents). Commands output YAML by default; use `--output json`
for JSON.

### Global Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--output` | `yaml` | Output format (`yaml`, `json`) |
| `--connect-timeout` | `10s` | TCP connection timeout (e.g. `10s`) |
| `--max-time` | `30s` | Maximum time per request |
| `--retries` | `3` | Number of retries on failure |

### Config

Create `~/.config/redmine-cli/config.yaml`:

```yaml
url: https://redmine.example.com
auth:
  type: api_key
  key: your-api-key-here
```

Auth types: `api_key`, `basic`, `oauth2`.

### Commands

```
# Issues
redmine issue list [--project PROJECT] [--limit N] [--offset N] [--sort FIELD]
                   [--all] [--top N] [--fields FIELDS] [--query QUERY_ID]
                   [--contains TEXT] [--regex PATTERN] [--case-insensitive]
                   [--include journals]
redmine issue get <ID> [--include journals] [--fields FIELDS]
redmine issue grep --text TEXT [--in description,notes]
                   [--project PROJECT] [--parent-id ID]
redmine issue create --project PROJECT --subject SUBJECT
                   [--description DESC] [--parent-id ID] [--tracker ID]
                   [--status ID] [--priority ID] [--assignee ID]
                   [--start-date YYYY-MM-DD] [--due-date YYYY-MM-DD]
                   [--estimated-hours N] [--fixed-version-id ID]
                   [--category-id ID] [--watcher USER_ID]
                   [--custom-field ID=VALUE]
redmine issue update <ID> [--subject SUBJECT] [--status STATUS]
                   [--assignee USER] [--done-ratio N] [--notes TEXT]
                   [--start-date YYYY-MM-DD] [--due-date YYYY-MM-DD]
                   [--estimated-hours N] [--fixed-version-id ID]
                   [--category-id ID]
                   [--watcher USER_ID] [--unwatcher USER_ID]
                   [--custom-field ID=VALUE]
redmine issue delete <ID>

# Issue relations
redmine issue relation add <FROM> <TO> --type TYPE [--delay DAYS]
redmine issue relation list <ISSUE-ID>
redmine issue relation remove <RELATION-ID>

# Metadata discovery
redmine tracker list
redmine status list
redmine priority list
redmine category list --project PROJECT

# Projects
redmine project list [--limit N]
redmine project get <IDENTIFIER>
redmine project create --name NAME --identifier IDENTIFIER [--description DESC]
redmine project delete <IDENTIFIER>

# Users
redmine user list [--limit N]
redmine user get <ID>
redmine user current

# Time entries
redmine time-entry list [--project PROJECT] [--issue ISSUE] [--limit N]

redmine time-entry delete <ID>

# Wiki
redmine wiki list --project PROJECT
redmine wiki get --project PROJECT --page TITLE

# Versions
redmine version list --project PROJECT

# Memberships
redmine membership list --project PROJECT [--limit N]

redmine membership remove <ID>

# News
redmine news list [--project PROJECT] [--limit N]
redmine news get <ID> [--include attachments,comments]
redmine news create --title TITLE [--project PROJECT]
                    [--summary SUMMARY] [--description DESC]

# Groups
redmine group list [--builtin] [--limit N]
redmine group get <ID> [--include users,memberships]
redmine group create --name NAME [--users 1,2]
redmine group update <ID> [--name NAME] [--add-users 1,2] [--remove-users 3]
redmine group delete <ID>

# Queries
redmine query list [--limit N]

# Custom fields
redmine custom-field list

# Attachments
redmine attachment get <ID> [--output-file FILE]
redmine attachment update <ID> [--description DESC] [--filename NAME]
redmine attachment delete <ID>
redmine upload --file PATH [--filename NAME]
```

## Dependencies

- [pb33f/libopenapi](https://github.com/pb33f/libopenapi) — OpenAPI 3.0 parsing, bundling, validation, code generation
- [urfave/cli](https://github.com/urfave/cli) — CLI framework
- Docker — required for spec generation (runs MySQL + Redmine)

No Ruby, Node.js, or Python required on the host. Docker is only needed for spec
regeneration, not for using the CLI tools.

## Releasing

This monorepo has two independent release tracks with separate tag prefixes:

| Component | Tag pattern | Workflow |
|-----------|-------------|----------|
| Redmine plugin | `plugin/v*.*.*` | `.github/workflows/release-plugin.yml` |
| CLI binaries | `cli/v*.*.*` | `.github/workflows/release-cli.yml` |

### Plugin release

```bash
git tag plugin/v0.3.0
git push origin plugin/v0.3.0
```

Archives: `.tar.gz` and `.zip` of `plugin/redmine_openapi_generator/`.

### CLI release

```bash
git tag cli/v0.5.0
git push origin cli/v0.5.0
```

Archives: `.tar.gz` per binary in `cmd/` (linux-amd64). Pushing a bare `v*.*.*`
tag will not trigger the release workflow; it must start with `cli/v`.

Both workflows run tests before creating the release. Pushing to `main` only
triggers CI for the files that changed (plugin paths for the plugin workflow, CLI
paths for the CLI workflow).
